The secondary brain, end to end — v3.2

Every Claude Code and Codex session on this machine is captured to an append-only SQLite ledger on C:, distilled by an LLM into cited memories, and projected to Markdown you can open in Obsidian. Delivery is progressive: deterministic orientation at session start, memory-only retrieval during a session, and deeper all-source retrieval on demand. Nothing in the brain leaves the machine except the consolidation call.

Hookcycle paths — three hooks, three different jobs

The same persistent ledger serves all three hooks, but their behavior is intentionally different: SessionStart derives a surrogate query from recent evidence and runs a one-list identity RRF over Memory BM25; UserPromptSubmit fuses Memory BM25 and Vector lists before applying delivery gates; SessionEnd writes the boundary that closes the episode.

Hooks are lifecycle callers; they are not the retrieval engine.

Retrieval does not require a hook. brain_search is an MCP adapter over the same BrainQueryService reached by brain.exe CLI. UserPromptSubmit automatically selects a memories-only two-list query with stricter delivery gates. SessionStart uses recent evidence to derive a query, calls the same fused search implementation, and receives a one-list identity RRF because only Memory BM25 is active on that hook path. SessionEnd appends a boundary, and explicit MCP/CLI searches can run at any point.

All three hooks are harness-invoked in both agents. Codex MCP is configured. The supported Claude user-scoped MCP installer and verifier are implemented, but installation remains an explicit operator action and was not performed by this architecture update. Manual CLI fallback is available to both; automatic fallback after MCP failure is not.

Capture was covered. Push now is too.

Seven of their nine hooks are redundant here because the transcript already holds what those hooks capture. But capture is not all those hooks do — UserPromptSubmit also injects back into the conversation, and for a long time this system did not travel that direction at all: the brain pushed exactly once, at session start. A session that ran for hours and pivoted to a different subject was never re-oriented.

Shipped. The brain now sits on UserPromptSubmit alongside CodeGraph and runs a memories-only query on each substantive prompt: Memory BM25 and Vector similarity fused as two ranked lists. Cross-source graph expansion contributes nothing under this filter. Most of the work is restraint, because a push on every message has the opposite failure mode from a push on none:

Never repeat — a memory reaches a session at most once, and a session takes at most twenty in total. Silence is the common answer — short prompts, no new matches, or nothing above the floor all return nothing. A stricter floor than search uses — FTS terms are OR-joined, so a prompt shares "is"/"the"/"of" with almost anything; measured, a question about unladen swallows retrieved a database-migration memory and would have injected it. 400 tokens, four memories, and a meter that names what it dropped — the session-start budget is 1,000–1,500 and fires once; this fires every message, and a session takes at most twenty memories in total.

The meter is the last line of every push, verbatim from a live run: [brain · 4 of 6 memories · 324 tokens · 2 dropped over budget]. A silent truncation reads as "that is all there was".

What the vector channel is, and is not, short of

One embedding provider against a competitor's six looks like the obvious gap. Building the mid-session push showed it is not the one that bites.

Provider count is not the constraint. A trustworthy threshold is.

Six providers buy redundancy and a choice of quality tier. They do not change what a bi-encoder can tell you, and running one model in-process is a real property: no sidecar, no network, no install step, and a binary that loads under Task Scheduler and Codex's sandbox where a dynamically-linked ONNX runtime does not.

What actually blocked the push was the absence of a similarity score anyone can put a floor under. An unsolicited injection needs to answer "is this relevant enough to interrupt with", and neither channel gives a usable yes/no. FTS terms are OR-joined, so BM25 returns something for every input — measured, a question about unladen swallows retrieved a database-migration memory. Cosine over all-MiniLM-L6-v2 is no better as a gate: the same model scored a turn about deployment speed at 0.478 and the turn that actually answered at 0.353, so no fixed cutoff separates them.

So the push ships with a keyword floor — two shared content terms — which is honest and deliberately conservative. It will miss a memory that is genuinely relevant and shares no vocabulary, which is the same gap the cross-encoder failed to close. The fix is query expansion, not more providers: expand the prompt into the words the corpus actually uses, and the floor stops being a handicap. Shipped as 6b431c0 — take the top five hits, harvest the terms appearing in at least two of them, append the best six and retrieve again. Selection is by document frequency, never raw count: a word repeated ten times in one document is about that document; a word in two is about the subject. It is fused as an extra channel rather than rewriting the query, so it cannot lose a result the plain query found — a rewritten query can drop the very document that seeded it. Live on this corpus: 0 lost, 1 newly reached.

Two indexes, and why neither queries the other

CodeGraph runs its own MCP server against both harnesses — v1.5.0, this repository at 229 files, 3,673 nodes and 11,732 edges in an up-to-date SQLite graph — and it also sits on UserPromptSubmit beside the brain's hook. The brain's internal codegraph provider, which was designed to proxy it, stays enabled: false on all three projects.

The separation is the integration.

A proxy was planned and dissolved. It would have built a second path to data both agents already reach directly, and it would have had to invalidate on every keystroke — a cache over a file watcher. What the two share is the agent, not a database.

The token claim is unmeasured here. CodeGraph publishes ~35% less cost and ~70% fewer tool calls across seven repositories; nothing on this machine has checked that, and it should not be repeated as though it had been. It is also why the brain's own A/B needed a third condition: both hooks fire on every prompt, so a two-condition split would credit the brain with whatever CodeGraph saved.

And both now fire in both harnesses. CodeGraph registered its own hook in Codex before we did; ours failed to launch there for five days because commandWindows quoted the executable and Codex does not strip it. That is the whole story of the “Codex has no push path” conclusion, and it was ours, not Codex’s.

Against the LLM Wiki pattern

Karpathy's LLM Wiki is a maintenance discipline, not a retrieval source: pages compiled once and then kept current, rather than another way to search. Measured against it, the architecture was there from the start and the operations were what was missing.

All four operations have closed. The last one was not where it was thought to be.

The sentence that indicted the original design: the LLM "doesn't just index it for later retrieval — it integrates it into the existing wiki." That was recorded here as a page problem — pages compound in coverage and are never revised. Measuring it found something sharper: 2,097 memories, 2,097 distinct ids, and zero supersession edges. The entire supersession lifecycle — schema, reader filters, MemoryStatus::Superseded, the tests — was code production had never once exercised. MemoryStatus::Superseded appeared in four places and every one was a read. Nothing wrote it.

So the gap was never that pages were unrevised. It was that claims were. Consolidation re-derives the same conclusion from overlapping event windows and files each as a new memory, so the vault accumulated duplicates and brain lint called them contradictions. brain reconcile --apply folds them: two appends per fold, nothing deleted — a new version of the keeper carrying the supersession edges, and a retirement version per loser. Live across all three projects: 97 contradictions folded, 142 memories superseded, 0 deleted, and subjects/backup.md now opens with "1 of these 35 claims has been revised in place, absorbing 4 earlier claims."

Ten contradictions remain, and they are the right ten: pairs filed twice on the same day from the same evidence, level on authority, date and evidence count, differing only in wording. Deciding whether two differently-worded bodies say the same thing is a reading of the text — exactly where derivation should stop, because the alternative is a coin-flip dressed as a rule, applied silently and never revisited.

What remains open is genuinely narrower than the row above claimed: a paragraph that rewrites the page rather than listing what it holds. That is 3.2b, it needs a live provider, and it is now the only unwritten feature in any wave.

This is a different thing from the llm_wiki provider in the codebase, which is a keyword searcher over a Markdown directory. Pointed at this vault it would search our own generated notes with a weaker index than the FTS5 already running over the same memories. Shipping the provider is not adopting the pattern, and adopting the pattern did not need it.
